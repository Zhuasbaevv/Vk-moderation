# VK Chat Manager Bot

Каркас бота-менеджера бесед ВКонтакте на Python (vkbottle), реализующий
иерархию ролей и команды модерации: кик/мут/бан, «сетки» бесед
(`/sban`, `/gban` и т.д.), глобальные беседы, логирование, режим тишины.

## Иерархия ролей (от младшей к старшей)

```
user            Пользователь (без роли)
senior_staff    Старший состав
leader          Лидер
tracker         Следящий
senior_tracker  Старший следящий
leadership      Руководство
creator         Создатель
```

Правило: пользователь не может мутить/банить/кикать людей с ролью выше или
равной своей. Только Создатель может действовать на равных/старших и на
самого себя.

## Установка

```bash
cd vk_moderation_bot
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
```

Заполните `.env`:

- `VK_TOKEN` — токен сообщества (Управление сообществом → Работа с API → Ключи доступа).
  Нужны права: **сообщения сообщества**, **управление сообществом** (или как минимум
  доступ к Bots Long Poll API).
- `VK_GROUP_ID` — ID сообщества (число, без минуса).
- `CREATOR_IDS` — ваш VK ID (и через запятую — ID других создателей), им будет
  автоматически выдана роль `creator` при первом запуске.
- В настройках сообщества включите **Long Poll API** (или используйте Callback API,
  адаптировав `main.py`).

Запуск:

```bash
python main.py
```

## Префиксы и алиасы

Команды распознаются с префиксами `/`, `!`, `+`, `.` (например, `/kick`,
`!kick`, `+kick`, `.kick` — все сработают). Русские алиасы вроде `бан`,
`мут`, `зов` тоже работают — список в `commands_meta.py`, вывод пользователю
доступен через `/alt`.

Если у автора сообщения не хватает роли — бот отвечает `❌️ Недоступно`.

## Иерархия сеток бесед (организация → направление → холдинг)

Помимо плоских «сеток» (`/setpull`), сетки теперь можно вкладывать друг в
друга: сетка организации → сетка направления → сетка «все организации».
Кик/бан/зов, выполненные в беседе организации, каскадом поднимаются вверх
по всей цепочке.

Настройка (пример: организация «Л-ОПГ» → направление «Криминальные» →
общая беседа всех организаций):

1. В беседе Л-ОПГ (может быть несколько чатов этой организации):
   `/setpull 101` — у организации своя сетка №101.
2. В беседе направления «Криминальные» (там же Старший следящий направления,
   следящие/лидеры/старшие составы всех организаций этого направления):
   `/setpull 10` — у направления своя сетка №10.
3. Находясь в чате Л-ОПГ, привязываем сетку организации к сетке направления:
   `/setdirection 10` — теперь сетка 101 (Л-ОПГ) вложена в сетку 10
   (Криминальные).
4. В общей беседе всех организаций: `/setpull 1` — сетка №1 — это холдинг.
5. Находясь в беседе направления «Криминальные» (сетка 10), пишем
   `/setholding 1` — теперь направление вложено в холдинг.

После этого: `/skick`, `/sban`, `/sunban`, `/szov`, выполненные в ЛЮБОЙ
беседе Л-ОПГ, затронут — все беседы Л-ОПГ + беседу направления «Криминальные»
+ общую беседу всех организаций. Забаненный через `/sban` в беседе Л-ОПГ не
сможет зайти повторно ни в один из этих трёх уровней — бан ставится сразу на
всю цепочку сеток.

Направлений может быть сколько угодно (в вашем случае — 3: социальные,
силовые, криминальные) — просто повторите шаги 1–3 для каждой организации
каждого направления и шаг 5 для каждого направления.

## Инлайн-кнопки

- **`/nlist` и `/nonick`** теперь с пагинацией (по 50 пользователей на
  страницу) и кнопками под сообщением: «◀️ пред. страница», «Без ников» /
  «С никами» (переключение между списками прямо в том же сообщении, без
  повторного ввода команды), «След. страница ▶️». Нажатие редактирует
  существующее сообщение, а не присылает новое.
- **Кнопка-антоним при каждом наказании**: `/mute` → кнопка «🔓 Снять мут»,
  `/ban` → «🔓 Снять бан», `/warn` → «🔓 Снять варн», `/sban` → «🔓 Снять бан
  в сетке», `/gban` → «🔓 Снять глобал-бан». По нажатию наказание снимается,
  сообщение редактируется (текст + ✅), кнопка исчезает. Проверяется тот же
  порог доступа, что и у самой команды (жмёт кто попало — получит
  всплывающее «❌️ Недоступно», действие не выполнится).
- Реализация — `bot_app/keyboards.py` (сборка клавиатур) и
  `bot_app/handlers/callbacks.py` (обработка нажатий, событие
  `message_event`). Регистрация идёт через `bot.on.raw_event(...)`
  **без** параметра `rules=` — в установленной версии vkbottle он не
  поддерживается у `raw_event` (это вызывало `KeyError: 'rules'` при
  старте); маршрутизация по конкретной кнопке (`payload["cmd"]`) сделана
  вручную внутри одного обработчика. Если после `pip install vkbottle`
  что-то не заработает "из коробки", проверьте актуальное имя dataclass'а
  для `GroupEventType.MESSAGE_EVENT` в установленной версии библиотеки
  (сами методы API — `messages.send_message_event_answer`,
  `messages.edit` — часть протокола VK и не меняются). Обработчик
  редактирования сообщений (`handlers/message_logger.py`) сделан по тому же
  принципу, но подписан на событие через обычную строку `"message_edit"`
  (не через `GroupEventType.MESSAGE_EDIT`) — так надёжнее, если в
  установленной версии vkbottle нет такого имени в enum.

  **Если бот не логирует редактирование сообщений** — почти наверняка дело
  не в коде, а в настройках сообщества: VK по умолчанию НЕ присылает
  событие `message_edit`, пока оно явно не включено отдельным чекбоксом
  (это не то же самое, что "Новое сообщение"). Проверьте: Управление
  сообществом → Работа с API → Long Poll API (или Callback API) → список
  событий → включите «Редактирование сообщения». Без этой галочки событие
  не придёт вообще, при любом коде.

## Время в московском часовом поясе

Все даты, которые бот показывает пользователю (последняя активность,
дата бана/варна, время окончания мута) — переводятся в МСК (UTC+3) и
выводятся в формате `2026-09-16 19:43:28 МСК (UTC+3)`. Внутри БД время
по-прежнему хранится в UTC (`utils.format_msk()` конвертирует только при
показе).

- **Уведомления о кике/бане в сетке/глобале шлются только туда, откуда
  реально кикнули** — `/skick`, `/sban`, `/gban`, `/gkick` теперь собирают
  список бесед, где `kick_member` реально сработал, и рассылают
  подтверждение только по нему, а не по всем беседам сетки/списка.
- **Автобан за самостоятельный выход** (`/leaveban`, `/sleaveban`,
  `/gleaveban`, доступ — Руководство и выше) — если человек сам выходит из
  беседы, бот банит его (в этой беседе / по всей сетке / глобально —
  смотря что включено), чтобы он не смог вернуться по кнопке "Вернуться"
  или через повторное приглашение. Каждая из трёх команд — независимый
  переключатель вкл/выкл, как `/quiet`.

## Как задать роль пользователю

Управление ролями через Telegram-бота (как в вашем ТЗ) в этот каркас не
включено — это отдельная интеграция (например, общая БД или HTTP API между
двумя ботами). Внутри этого проекта роль можно назначить напрямую в БД:

```python
import asyncio
from bot_app import database

async def main():
    await database.init_db()
    await database.set_role(123456789, "leader")

asyncio.run(main())
```

Либо добавьте собственную команду `/addrole` в `creator_cmds.py` — там уже
есть `TITLE_TO_ROLE` в `hierarchy.py` для парсинга русских названий ролей.

## Что реализовано по вашему ТЗ

- Иерархия и проверка прав на все команды.
- `/getid`, `/stats` (с ограничением видимости по рангу), `/info`, `/help`
  (показывает только доступные пользователю разделы), `/alt`.
- `/clear` (алиас `чистка`) — ответом на сообщение удаляет его; нельзя
  удалить сообщение того, чья роль выше или равна вызвавшему.
- `/kick`, `/mute` (с автоматическим снятием по истечении времени и
  автоудалением сообщений замученного), `/unmute`.
- `/staff`, `/nlist`, `/nonick`, `/getacc`, `/getban` (три блока: глобально /
  сетка / беседа).
- `/skick`, `/zov`, `/online`, `/onlinelist`.
- `/ban`, `/unban`, `/banlist`, `/quiet` (блокирует сообщения "Старшего
  состава").
- `/sban`, `/sunban`, `/szov` — действуют на все беседы внутри «сетки»,
  привязанной через `/setpull`.
- `/gban`, `/gunban`, `/gkick`, `/gzov` — действуют на все беседы, добавленные
  через `/global`; `/setinfo` — задаёт текст для `/info`.
- `/setpull`, `/delpull`, `/global`, `/delglobal`, `/nickname`, `/go`, `/logs`,
  `/setdirection`, `/delsetdirection`, `/setholding`, `/delsetholding`.
- **`/logs`** — назначает ТЕКУЩУЮ беседу единственным приёмником логов.
  **`/go`** — включает/выключает логирование текущей беседы (повторный вызов
  выключает, как `/quiet`). Каждое сообщение из логируемой беседы
  пересылается (настоящим `forward`, со всеми вложениями) в лог-беседу с
  заголовком:
  ```
  1. Беседа: <название беседы>
  2. NickName: <ник или тег ВК>
  3. Время: 2026-09-17 16:28:00 МСК (UTC+3)
  4. Номер сообщ: #42
  5. Ответил на сообщение: #17     (если это ответ)
  ```
  Номер `#N` — сквозной для каждой логируемой беседы отдельно. При
  редактировании сообщения номер не меняется — бот просто присылает лог
  заново с тем же `#N` (VK сообщает о редактировании отдельным событием
  `message_edit`, которое тоже обрабатывается).
- `/warn`, `/unwarn` (снимает последний активный), `/getwarn` (активные),
  `/warnhistory` (вся история, включая снятые — кто выдал и кто снял),
  `/warnlist` (все пользователи с активными варнами и их количеством).
  Доступ — как у `/kick`/`/mute` (уровень «Лидер»). Автонаказание за N варнов
  не реализовано — при необходимости легко добавить проверку `total >= N`
  сразу после `database.add_warn(...)` в `cmd_warn`.
- Автоматическое исключение забаненного пользователя при попытке добавить
  его в беседу (проверяются глобальный бан → бан по сетке → бан в беседе).
  Если пользователь НЕ забанен — бот присылает приветствие с упоминанием
  по имени: `"Имя, добро пожаловать в беседу! Не забудь прочитать
  закреплённое сообщение! Посмотреть информацию о проекте: «/info»"`.
- **Беседы регистрируются автоматически** — как только бота добавили в чат
  (или пришло первое сообщение), чат попадает в список `known_chats`.
  `/gban`, `/gunban`, `/gkick`, `/gzov` действуют по этому списку — указывать
  ID беседы или вручную гонять `/global` по каждому чату не нужно.
  Команда `/global`/`/delglobal` при этом осталась рабочей и независимой —
  для своих собственных целей (метка/группа беседы).
- **Ники**: `/setnick` (`snick`, `ник`), `/removenick` (`rnick`), `/getnick`
  (узнать ник конкретного человека) — доступны
  с роли «Лидер».
- **Роли**: именные команды `/addld` (Лидер, порог — Старший следящий+),
  `/addsup` / `/addsensup` (Следящий / Старший следящий, порог — Руководство+),
  `/addadmin` (Руководство, порог — только Создатель). У каждой есть
  s-версия (`/saddld`, `/saddsup`, `/saddsensup`, `/saddadmin`) — выдаёт роль
  **только в сетке беседы** (см. ниже), а не глобально.
  Также есть числовые команды `/role [тег] [1-5]` и `/srole [тег] [1-5]`
  (глобально / в сетке) с той же картой: 1 — Старший состав, 2 — Лидер,
  3 — Следящий, 4 — Старший следящий, 5 — Руководство. Роль «Создатель» (6)
  через команды не выдаётся.
  Снятие роли: `/removerole` / `/rrole` (глобально), `/sremoverole` /
  `/srrole` (в сетке) — порог доступа зависит от уровня снимаемой роли.
- **Роли в сетке бесед**: пользователь может иметь отдельную роль только в
  рамках одной "сетки" (`/setpull`), не затрагивающую его глобальную роль.
  В любой беседе этой сетки при проверке прав берётся более старшая из двух
  ролей (глобальная и "сеточная"). Truly-глобальные команды (`/gban` и
  другие `/g...`, `/setinfo`) при этом смотрят **только** на глобальную
  роль — роль, выданная лишь в одной сетке, не даёт прав действовать сразу
  во всех беседах бота.
- **Бот отвечает как реплай** на сообщение с командой (а не отправляет
  отдельное сообщение) — везде, КРОМЕ `/zov`, `/szov`, `/gzov`, `/online`,
  `/onlinelist`, где по-прежнему отправляется обычное сообщение (там это
  уместнее из-за формата с массовыми упоминаниями).
- **Определение цели команды** (ответ на сообщение / тег / ссылка) уже
  всегда приоритетно проверяет именно reply: `/mute 30 оскорбление` в ответ
  на сообщение человека корректно берёт цель из reply, а "30" и
  "оскорбление" распознаются как минуты и причина — это не нужно было
  отдельно чинить, работало уже в исходной версии `resolve_target`.
- Рассылка сообщения о бане/кике **во все беседы сетки** (`/sban`, `/sunban`,
  `/skick`) и **во все известные беседы** (`/gban`, `/gunban`, `/gkick`) —
  раньше `/skick` отправлял подтверждение только в текущий чат, это
  исправлено.

## Точки расширения (не реализовано «под ключ», но заложено в архитектуре)

- **Интеграция с Telegram-ботом** для синхронизации ролей/ников — сейчас роли
  живут только в локальной SQLite.
- **Callback API вместо Long Poll** — если сообщество уже настроено на
  Callback, замените `bot.run_forever()` на `bot.run_forever()` через
  `aiohttp`-сервер (см. документацию vkbottle: `BotPollingRunner` →
  `BotWebhookRunner`).
- Реальная пересылка логов сообщений в лог-чат — уже реализована (`/go`,
  `/logs`, `handlers/message_logger.py`).
